# WorkFlowSync — Технічне завдання (жива специфікація)

Цей документ — єдине джерело вимог до продукту. Його оновлюють до або разом із кожною зміною
поведінки. Він має бути читабельним для людини і достатньо точним, щоб інший агент реалізував
функцію без історії чату.

## 1. Суть продукту

**WorkFlowSync** — портативна Windows-програма, яка веде **одностороннє дзеркало з пам'яттю**:
з однієї або кількох мережевих папок (джерело, змінюване, чуже) у локальні папки всередині
OneDrive (ціль, власна).

Проблема, яку розв'язує: типові синхронізатори (FreeFileSync) не мають пам'яті про історію.
Щоб локально видалений файл не повертався, доводиться вручну вести список виключень — у поточному
`batch.ffs_batch` таких записів **22 569**, файл 6,6 МБ. WorkFlowSync замінює цей список
базою стану.

Користувач: один, звичайний користувач Windows без прав адміністратора. Автор і замовник —
Білик Ігор.

### 3.1 Три правила замовника (стисло, повний текст у F1)

1. Видалення в джерелі **не впливає** на локальну копію.
2. Додавання в джерелі **додається** локально (нові папки й файли; оновлення незмінених локально файлів).
3. Локальне видалення/переміщення/зміна **не впливає** на джерело і **більше ніколи** не підтягується заново.

### 3.2 Дата появи, вікно перенесення і автоочищення (стисло, повний текст у F3)

Для кожного об'єкта фіксується момент, коли сканер уперше побачив його в джерелі (`first_seen`),
а не дата створення чи зміни файлу. На першому проході пари (база порожня) за неї править
`min(ctime, mtime)`; далі — момент, коли файл побачили ми.

Для кожної пари в режимі «дзеркало» є два незалежні вікна:

- **Переносити лише те, що з'явилося за останні N днів** (`maxAge`) — фільтр на вході. Старіші
  файли не копіюються і не оновлюються; у джерелі вони лишаються недоторканими, з локальної теки
  не видаляється нічого.
- **Автоочищення** (`autoClean`) — наші копії, додані понад N днів тому, переносяться в Кошик
  і не повертаються. У джерелі не зникає нічого.

## 5. Нефункціональні вимоги

- **Платформа**: Windows 10/11 x64. .NET 8 LTS, self-contained single-file, без інсталяції
  рантайму. Два exe: `WorkFlowSync.exe` (GUI, Avalonia 11.3) і `wfs.exe` (консоль). Маніфест `asInvoker` (ніколи не просити підвищення прав), `longPathAware`.
- **Права**: усе працює від звичайного користувача: файли, Кошик, автозапуск, Планувальник
  (лише «коли користувач увійшов», без «найвищих прав»).
- **Продуктивність**: повний прохід дерева ~50 тис. папок / 500 тис. файлів по SMB — орієнтир
  20–60 с на LAN. Вартість проходу ≈ O(папок), а не O(файлів). Деталі у F5.
- **Надійність**: жодна дія не має руйнівних наслідків для джерела (відкриття лише на читання).
  Локальні видалення — тільки у Кошик. Недоступне джерело або гілка = пропуск, не помилка стану.
  Стан пишеться транзакційно; раптове вимкнення не ламає базу.
- **OneDrive**: сканер цілі читає лише атрибути — не гідратує заглушки Files On-Demand. У дзеркалі
  створюються лише справжні папки й файли (без symlink/junction).
- **Приватність**: програма не має мережевих з'єднань, крім доступу до SMB-джерел; жодної
  телеметрії. У логах — шляхи файлів (можуть містити персональні дані) → логи зберігаються поруч
  із програмою, у git не потрапляють.
- **Кодування**: UTF-8 усюди (консоль, логи, конфіг). Українські імена файлів — базовий сценарій.
- **Двомовність**: Повний інтерфейс підтримує дві мови — українську (`uk`) та англійську (`en`), з можливістю автоматичного визначення за мовою системи (`system`). Перемикання мови відбувається миттєво на льоту без перезапуску вікон. Мовні файли організовані у форматі стандартних JSON-конфігів (`Locales/uk.json`, `Locales/en.json`) із підтримкою зовнішніх перекриттів у папці `locales/`.
- **Ліцензія**: MIT.
