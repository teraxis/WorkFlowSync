# Changes for the Next Release

Keep only completed, user-visible changes since the previous release. Adapt headings and entries to
the product's user-facing language. Do not include implementation details, code symbols, file names,
commits, or agent attribution.

## Fixed

- Бейдж стану активного завдання у списку завдань помилково показував «виконується» замість «активне», через що складалося хибне враження, ніби завдання постійно виконується або зависло. Тепер у спокійному стані відображається «активне», а статус «перевіряється…» зі смугою прогресу з'являється лише безпосередньо під час перевірки та синхронізації.

- Усунуто збій фонового циклу перевірок через некоректне значення режиму спостереження в конфігурації, додано автоматичне очікування блокувань SQLite (`busy_timeout`) для уникнення взаємних блокувань інтерфейсу та фонового сервісу, а також забезпечено надійне закриття черги сканера файлової системи у разі скасування.

- Налаштування «зберігати лише те, що з'явилося за останні N днів» робило не те, що обіцяло:
  старий файл спершу повністю копіювався з мережевої папки, а вже наступною перевіркою
  переносився в Кошик. На великому архіві це означало години марного копіювання мережею.
  Тепер такі файли не переносяться взагалі, а прибирання в Кошик стало окремим налаштуванням
  «Автоочищення», яке типово вимкнене.
  **Що це означає для наявних пар:** число днів, яке ви вже задали, тепер працює як фільтр на
  перенесення. Те, що вже накопичилося в локальній папці, більше не прибирається саме собою —
  якщо вам потрібне саме прибирання, увімкніть «Автоочищення» в налаштуваннях пари.

- Напис на синіх кнопках («Додати пару», «Синхронізувати») був майже чорним і зливався з тлом,
  хоча іконка поруч малювалася білою. Тепер напис білий, як і мало бути.

- На слабких комп'ютерах перевірка папок займала весь процесор, і вікно програми переходило
  в стан «не відповідає». Тепер прохід виконується зі зниженим пріоритетом і меншою кількістю
  паралельних читань, а живий журнал у вікні оновлюється не частіше ніж кілька разів на секунду.

- Автозапуск у режимі «зі значком в області сповіщень» показував вікно програми під час
  завантаження Windows. Тепер програма стартує тихо: лише значок біля годинника.

- Перемикачі автозапуску були недоступні, якщо поруч із програмою немає консольного файла,
  хоча для варіанту «в області сповіщень» він не потрібен.

## Changed

- Повністю оновлено візуальний дизайн бокового меню навігації та списку завдань:
  - У боковому меню додано індикатор-бейдж із кількістю завдань, оновлено піктограми, а внизу меню розміщено статусний блок із діагностикою роботи програми («Усі системи в нормі» / час останньої перевірки).
  - Картки завдань перероблено у сучасному стилі інформаційного дашборду: додано виділені блоки джерела та призначення з піктограмами сховищ, перемикач активності завдання (із фіксованою позицією без зсуву при довгих назвах), спрощені й охайно вирівняні чипи параметрів (посилання, погодження, стеження, виключення, а розклад показується лише при вимкненому відстеженні; вилучено дублюючі блоки режиму та версійності).
  - Усунуто небажані розділювальні лінії після останнього елемента в нижньому блоці параметрів картки завдання (бордер відображається лише за наявності наступних блоків).
  - Блок чипа «Стеження» в картці завдання тепер відображається виключно в тому разі, коли відстеження увімкнено у налаштуваннях пари (`WatchMode.On`).
  - Кнопку дій «⋮» перенесено у верхній правий кут картки завдання на місце колишнього перемикача.
  - Додано динамічні іконки відповідно до типу джерела/призначення тек у картках завдань (локальний диск, мережевий сервер `IconServer` для SMB/мережі, знімний носій/USB `IconUsb`).
  - Візуально виділено блоки тек джерела та призначення за допомогою тонізованого підкладення та тонкої рамки `BorderSubtle`.
  - Поведінку та положення скролу в розділі «Завдання» повністю ідентифіковано та узгоджено з розділом «Налаштування» (ідентичний відступ справа `Padding="0,0,12,0"` та налаштування прокручувальної смуги).
- Зміна мови в розділі **«Налаштування»** тепер застосовується миттєво для всіх елементів інтерфейсу, меню та сповіщень без необхідності перезавантаження програми.
- Спрощено та розвантажено інтерфейс розділу **«Налаштування»**: вилучено текстові описи й підказки під перемикачами та параметрами.
- У розділі **«Налаштування»** → **«Повідомлення»** напис перед випадним списком змінено на **«Тип повідомлень»**, а ширину селектора узгоджено з елементами нижче.
- Зі сторінки **«Журнал подій»** вилучено кнопку «Синхронізувати зараз», а з верхньої панелі головного вікна — кнопку «Погодження змін».
- Оновлено та вдосконалено вікно «Погодження змін»:
  - Виділення рядків тепер строго обмежене рамкою картки з акуратним скругленням і не виходить за межі блоку.
  - Замість текстових плашок додано візуальні круглі бейджі з іконками типів змін у стилі FreeFileSync (зелений плюс для доданих, червоний кошик для видалених, бурштиновий олівець для змінених, синя стрілка для перейменованих).
  - Замість громіздкого горизонтального розміщення чекбоксів реалізовано компактні випадні списки-селекти («Селект завдань» та «Селект типів змін») із чекбоксами всередині, підтримкою вибору довільних комбінацій, підрахунком подій, станом «Обрати всі» (трипозиційний перемикач) та лаконічним зведенням на кнопці.
  - Виправлено зникнення списку змін при відкритті вікна: фільтрація тепер надійно ініціалізується для всіх наявних завдань і типів без помилкового приховування записів.
  - Розділювач груп завдань оформлено єдиним охайним блоком на всю ширину списку з назвою завдання, лічильником записів, груповим чекбоксом та повними шляхами обох тек (`Тека 1 → Тека 2`).
  - Прибрано зайві загальні заголовки колонок («Джерело», «Зміна», «Ціль», «Дії»), що суттєво розвантажило інтерфейс.
  - Стрілка напрямку дії біля іконки зміни тепер відображається без фонового кружечка та має колір, що відповідає типу зміни (зелений для додавання, червоний для видалення, бурштиновий для модифікації, синій для перейменування).
  - Під центральним бейджем прибрано зайві написи: збільшення або зменшення розміру (`+5 KB` / `−2 KB`) відображається безпосередньо біля розміру файлу, який змінився, а дату зміни виділено кольором без рамки-бейджів.
  - Кнопки дій у рядках («Підтвердити», «Залишити як є», «Повернути») забезпечено бездоганним математичним та оптичним центруванням іконок по вертикалі та горизонталі.
  - Верхні кнопки масових операцій («Підтвердити всі», «Залишити всі як є», «Повернути все») та кнопку оновлення узгоджено за розмірами, стилями й піктограмами.
  - Дати файлів тепер відображаються у точному форматі `dd.MM.yyyy HH:mm:ss`.
  - У спливаючому вікні сповіщень трею («Останні зміни») блок виявлених змін оновлено: прибрано іконку щита та стрілку, замість неї розміщено бейдж із кількістю дій, а фон при наведенні курсора став рівномірним без темних зон.
- Термінологію в інтерфейсі приведено до єдиних стандартизованих назв: розділ «Папки» перейменовано на **«Завдання»**, розділ «Синхронізація» — на **«Журнал подій»**, кнопка додати — **«Додати завдання»**, а в описі та параметрах «папки» замінено на **«теки»** («Перша тека» та «Друга тека» / «Вихідна тека» та «Кінцева тека»).
- База, у якій програма зберігає історію, стала приблизно вдвічі меншою і читається швидше.
  Перехід відбувається сам при першому запуску: поруч зі старою базою залишається її резервна
  копія (`state.db.v1-backup`) — її можна видалити, коли переконаєтесь, що все на місці.
- Перерване копіювання більше не втрачає зроблене: програма записує проміжні результати під час
  роботи, а не лише наприкінці. Раніше вимкнення комп'ютера посеред першого копіювання великої
  папки збивало дати появи файлів, а з ними й строк зберігання.

- Програма більше не запускається двічі. Якщо вона вже працює — у вікні або в області сповіщень —
  повторне клацання по ярлику просто виводить наявне вікно наперед. Раніше можна було отримати дві
  копії, які заважали одна одній і перезаписували налаштування.
- Дрібний сірий текст (шляхи папок і рядок під ними) став помітно контрастнішим — раніше він був
  на межі розбірливості.

- Написи на синіх кнопках стали читабельнішими: у світлій темі кнопка глибшого синього, тож білий
  напис на ній чіткий; у темній темі напис тепер темний на яскравій кнопці — раніше білий на
  світло-синьому був на межі розбірливості.

- У картці пари замість трьох окремих кнопок — меню ⋯ («Перевірити зараз», «Редагувати…»,
  «Видалити»).
- Лічильники в налаштуваннях і діалозі пари перемальовані: кути кнопок більше не обрізаються.
- Блок «Файли програми» вирівняно за шириною з рештою; у ньому лише папка програми та строк
  зберігання журналів.

- Сторінка «Синхронізація» спрощена до кнопки «Синхронізувати» та історії; історія
  переноситься по рядках без горизонтальної прокрутки.
- Нові іконки меню та кнопок (єдиний набір), тонкі смуги прокрутки у власній смузі, скруглені
  кнопки лічильників.
- Зміни налаштувань і пар зберігаються автоматично — кнопки «Зберегти», «Скасувати зміни» і
  «Перевірити» прибрано; рядок повідомлення внизу з'являється лише за потреби.
- Лічильники й випадні списки приведено до спільного стилю; вміст сторінок доходить до смуги
  прокрутки без широкого порожнього краю.

## Added

- **Автоматичне оновлення через GitHub.** Програма при запуску тихо перевіряє наявність нової версії на GitHub. Якщо знайдено — біля годинника з'являється повідомлення з кнопками «Оновити», «Нагадати пізніше» або «Не нагадувати про це оновлення». Оновлення завантажується з прогрес-баром і встановлюється автоматично з перезапуском. У налаштуваннях — checkbox «Автооновлення».
- **Повна двомовність (українська та англійська мови).** Додано вибір мови інтерфейсу в розділі «Налаштування» → «Зовнішній вигляд» (українська, англійська або автоматично за мовою Windows). Перемикання мови відбувається миттєво для всіх відкритих вікон, діалогів та меню біля годинника без перезапуску програми. Усі написи та описи перевірено та адаптовано для легкості сприйняття користувачем без штучного машинного стилю.
- **Погодження змін та версіонування у двобічних теках.** Для двобічної синхронізації додано режим модерації (`requireApproval`): будь-які локальні створення, зміни, видалення чи перейменування у другій теці не переносяться на мережу/сервер автоматично, а потрапляють у чергу погодження.
- **Окреме вікно «Погодження змін» та банер у списку останніх змін.** Зручне порівняння станів «Було» і «Стало», підтвердження, скасування або відкат кожної зміни окремо або масово для всіх/вибраних записів, фільтрація за типом подій та пошук.
- **Резервні копії у прихованій теці `.wfsversions`.** Перед відкатом чи видаленням файлів копії зберігаються локально в прихованій теці з ротацією за віком (типово 30 днів) та обсягом (типово 5 ГБ).
- **Консольні команди `wfs pending`** (`list`, `approve`, `dismiss`, `revert`) для перегляду та керування чергою погодження з підтримкою JSON та групових дій.
- **Період перевірки тепер задається для кожної пари окремо** («Папки → ⋯ → Редагувати… →
  Перевіряти кожні N хвилин»). Спільного інтервалу в «Налаштуваннях» більше немає: одне число
  ніколи не підходило одночасно робочій теці, що змінюється щохвилини, і архіву на десятки тисяч
  тек, повний обхід якого коштує хвилин. Ваше попереднє значення при першому відкритті
  переноситься в кожну пару, тож нічого не зміниться непомітно. Якщо всі пари на паузі, програма
  більше не виконує порожніх перевірок.
- Вміст сторінок вирівняно: відступ зліва тепер такий самий, як справа до смуги прокрутки.
- У списку останніх змін з'явилися **іконки типів файлів** — системні, ті самі, що показує
  Провідник: Word, Excel, PDF, архіви впізнаються з першого погляду. Якщо для якогось типу іконки
  немає, показується кольорова позначка з розширенням.
- Іконку програми перемальовано: тепер вона різка на всіх розмірах — від 16 px біля годинника до
  256 px у Провіднику (раніше розмірів було чотири, тепер сім).
- Кнопка **«Очистити журнал»** на сторінці «Синхронізація»: прибирає показаний журнал і видаляє
  старі файли журналу (сьогоднішній лишається — у нього ще пишеться поточна перевірка).

- У списку останніх змін у кожного файла з’явилася кнопка з текою — відкриває папку й одразу виділяє в ній цей файл. Кількість файлів у списку тепер налаштовується («Налаштування» → «Повідомлення» → «Файлів у списку змін»).

- Налаштування повідомлень з’явилися у «Налаштуваннях» (картка «Повідомлення»): що показувати й
  тихі години. У рядку стану тепер видно, чи програма стежить за змінами і за скількома теками —
  якщо не стежить, пара перевіряється лише за інтервалом, і це помітно без заглядання в журнал.

- **Повідомлення про нові файли.** Після перевірки в куті екрана на кілька секунд з'являється
  повідомлення — **одне на перевірку**, а не по одному на файл: «Додано 12 нових файлів». Клік по
  ньому відкриває список останніх змін. Якщо щось пішло не так, повідомлення скаже саме про це.
  У налаштуваннях (поки що у файлі `config.json`) можна лишити «лише проблеми» чи вимкнути зовсім,
  а також задати тихі години — вночі буденні новини притримуються, але про проблеми програма
  скаже однаково.

- **Клік по значку біля годинника показує, що з'явилося.** Невелике вікно в куті екрана зі списком
  останніх файлів, які програма принесла у ваші папки: назва, тека, час і розмір. Подвійний клік
  відкриває файл у Провіднику, шестерня вгорі праворуч — головне вікно програми. Вікно зникає,
  щойно ви клацнете повз нього.

- **Зміни підхоплюються за секунди, а не за інтервалом.** У фоновому режимі програма тепер стежить
  за папками: щойно у відстежуваній теці з'являється або змінюється файл, вона синхронізує **саме цю
  теку**, не чекаючи наступної повної перевірки. Повна перевірка нікуди не ділася й лишається
  головною: швидка реакція лише додає, оновлює і **ніколи нічого не видаляє** — рішення про видалене
  ухвалює повна перевірка, коли бачить усю папку. Стеження вмикається в налаштуваннях пари
  («Стежити за змінами», типово автоматично).

- Захист від масової втрати файлів у повній синхронізації: якщо за один прохід мало б зникнути
  понад сотню об'єктів і понад п'яту частину папки, програма **не видаляє нічого** й пише про це в
  журнал — найчастіше це означає, що мережева папка доступна не повністю, а не що ви щось
  видалили. Коли ситуація нормалізується, наступна перевірка спокійно доведе справу до кінця.
  Крім того, перед кожним видаленням програма ще раз перевіряє цей самий файл на другому боці —
  це, зокрема, прибирає хибні видалення під час звичайного збереження документів Word та Excel.
- **Увага:** у мережевій папці Кошика не існує, тому видалення там **остаточне**. Тепер кожне таке
  видалення записується в журнал із повним шляхом.
- Нове налаштування пари «Файли з хмари» (для повної синхронізації): файли, що лежать лише в хмарі
  OneDrive, за замовчуванням **не завантажуються** — інакше синхронізація мовчки витягла б на диск
  усе, що ви свідомо звільнили.

- Пару можна синхронізувати по одній теці, не чекаючи перевірки всієї папки. Такий прохід **лише
  додає й оновлює**: нічого не видаляє й не позначає як видалене — це лишається за повною
  перевіркою. Поки що доступно з консолі; саме на цьому працюватиме миттєва реакція на зміни.

- У налаштуваннях пари з'явилося «Стежити за змінами»: автоматично (типово), завжди або ніколи.
  Перевірка за інтервалом працює в будь-якому разі — стеження лише скорочує очікування.
- У картці пари тепер видно, на якому сховищі лежить джерело: локальна папка, знімний носій
  чи мережева. Від цього залежить, наскільки швидко програма помічає зміни.

- Нова команда перевірки папки: показує, що це за носій (локальний диск, знімний, мережева папка
  в локальній мережі чи віддалена), скільки часу займає звернення до неї і чи надходять від неї
  сповіщення про зміни. Нічого в папці не змінює. Потрібна, щоб зрозуміти, чи зможе програма
  реагувати на зміни миттєво.
- У журнал проходу додано, скільки процесора й пам'яті він зайняв.

- Налаштування «Навантаження на процесор» («Налаштування» → «Продуктивність сканера»):
  помірне (типово), повне або низьке — для слабких комп'ютерів.

- Тип синхронізації для кожної пари: «Дзеркало (в один бік)» — як раніше, або «Повна синхронізація
  (в обидва боки)», де створення, зміни й видалення переносяться в обидві папки, а видалене
  потрапляє в Кошик. Тип обирається в налаштуваннях пари, а в картці пари між двома шляхами
  показано значок: одна стрілка для дзеркала, подвійна — для повної синхронізації.
- Пара, у якої обидві папки — та сама, або одна лежить усередині іншої, більше не приймається:
  такий запис відхиляється і у вікні пари, і у вручну відредагованому файлі налаштувань.

- Строк зберігання журналів («Налаштування → Файли програми → Зберігати журнали», 1–3650 днів,
  типово 30): старіші файли видаляються автоматично при наступному проході.

- Усі файли програми (config.json, база стану, журнали) зберігаються в папці, з якої її запущено;
  конфігурація створюється там одразу при першому запуску. У «Налаштуваннях» показано папку
  програми з кнопкою «Відкрити» і повні шляхи бази й журналів.
- Новий вигляд програми: світла й темна теми (перемикач у «Налаштуваннях», за замовчуванням —
  як у Windows), навігація ліворуч замість вкладок, сторінки «Папки», «Синхронізація» й
  «Налаштування», картки з чіткою ієрархією, власні іконки.
- Пару можна редагувати й видаляти прямо з її рядка (видалення — з підтвердженням).
- Інтерфейс очищено від зайвого: без підзаголовків, індикаторів і службових написів; імпорт із
  FreeFileSync — у «Налаштуваннях».
- У кожного рядка пари з'явилася одна кнопка **▶/⏸** і кружечок стану: зелений — пара
  перевіряється автоматично із заданим інтервалом, сірий — на паузі. Натискання діє одразу:
  щойно запущена пара перевіряється негайно, далі — за інтервалом. Поруч є кнопка
  **Перевірити зараз** для одноразової синхронізації однієї пари.
- Автоматична перевірка більше не потребує окремого вмикача: працюють ті пари, що позначені ▶.
  Стан пар запам'ятовується, тож після перезапуску програма продовжує перевіряти сама.
- Значок в області сповіщень: програма може працювати біля годинника й сама перевіряти папки.
  Меню значка — стан, «Відкрити вікно», «Синхронізувати зараз», пауза/запуск фонового режиму, «Вийти».
  Закриття вікна ховає програму в область сповіщень (вихід — через меню значка).
- Автозапуск при вході в Windows тепер на вибір: зі значком в області сповіщень або фоновим
  процесом без вікна.
- Власна іконка програми.
- Резидентний режим: програма може працювати у фоні й перевіряти мережеві папки за заданим
  інтервалом; зміни налаштувань підхоплюються без перезапуску.
- Автоматичний запуск без прав адміністратора — два перемикачі в «Налаштуваннях» (і команди
  `wfs autostart`, `wfs task`): запуск при вході в Windows або завдання Планувальника.
- Одночасно виконується лише один прохід для конфігурації, хоч звідки його запущено (вікно,
  Планувальник, фоновий режим).
- Логи старші за 30 днів видаляються автоматично.
- Для пари в режимі «Дзеркало» є два незалежні налаштування давності:
  **«Переносити лише те, що з'явилося за останні N днів»** — старіші файли просто не переносяться
  і не оновлюються. У мережевій папці вони лишаються недоторканими, а з локальної нічого не
  видаляється. Порожня папка під такі файли навіть не створюється.
  **«Автоочищення»** — файли, які програма додала понад N днів тому, переносяться в Кошик і більше
  не повертаються; папки, що спорожніли, теж прибираються, але повернуться, щойно в них з'явиться
  щось нове. Файли, змінені локально, автоочищення не зачіпає.
  Давність рахується від дати, коли файл побачила програма, а не від дати самого файлу. Виняток —
  перша перевірка нової пари: тоді за неї править дата створення/зміни файлу.
- Імпорт із FreeFileSync (кнопка на вкладці «Папки» або `wfs import-excludes`): список виключень
  переноситься як шаблони і як позначки «не повертати», тож перехід не повертає жодного раніше
  видаленого файлу.
- `wfs forget <шлях>` — забути позначку, щоб об'єкт знову скопіювався як новий.
- Синхронізація працює: нові папки й файли з мережевої папки копіюються в локальне дзеркало,
  оновлені в джерелі файли оновлюються, якщо локальну копію не чіпали; видалене в джерелі
  лишається локально; видалене, переміщене або змінене локально більше ніколи не повертається
  з джерела (у т.ч. нові файли в локально видаленій папці).
- Дата появи кожного об'єкта фіксується в момент, коли програма вперше побачила його в джерелі;
  для вже наявних на першому запуску файлів береться найраніша з дат створення/зміни.
- Лінки (junction/symlink) у джерелі проходяться і копіюються як звичайні папки; лінки, що ведуть
  «назад» (цикли), пропускаються з попередженням.
- Приховані та системні файли дзеркалюються.
- Недоступна мережева папка не вважається «порожньою»: пара пропускається, нічого не змінюється.
- Консоль: `wfs sync` (з `--dry-run` для перегляду плану без змін), `wfs status`; захист від
  одночасних запусків.
- Вкладка «Стан»: зведення за парами, «Показати план», «Виконати зараз», «Зупинити», живий лог.
- Графічний інтерфейс `WorkFlowSync.exe`: вкладка «Папки» — додавання, редагування й видалення пар
  «мережева папка → локальна папка» з вибором папок через системний діалог, режим лінків,
  термін зберігання і виключення; вкладка «Налаштування» — інтервал перевірки, база стану, папка
  логів, параметри сканера; перевірка й збереження конфігурації.
- Консольна утиліта `wfs.exe` з командами `config validate` і `version`; при запуску подвійним
  кліком вікно не закривається саме.
