# Випуск WorkFlowSync v0.3.18

Портативна версія для Windows x64.

## Виправлення та покращення

- **Сканування довгих шляхів понад 260 символів (`MAX_PATH`)**: `TreeScanner` тепер використовує системний префікс розширених шляхів Windows (`\\?\` та `\\?\UNC\`), що усуває `PathTooLongException` під час сканування глибоких каталогів за `LongPathsEnabled = 0`.
- **Безпечна обробка каталогів Cloud Files (OneDrive)**: каталоги з reparse points, у яких тимчасово недоступний reparse tag або які не є символьними посиланнями, більше не переривають сканування та не спричиняють помилкових поміток видалення (`cannot list: reparse tag unavailable`).
- **Детерміноване скорочення каталогів (R1)**: скорочення назв папок відбувається виключно на основі структури та довжини самого каталогу без прив'язки до довжини імені чи розширення окремих файлів. Усі файли в одній папці завжди розміщуються в однаковій канонічній цільовій папці.
- **Відновлення помилкових Tombstones (R6)**: файли, які через переривання сканування на довгих шляхах були помилково позначені як `Tombstone` у базі `state.db`, автоматично оживляються (`revive`) до статусу `Active` та переносяться на канонічний шлях у разі наявності їх на цільовому диску.
- **Очищення порожніх варіантів тек та копій конфліктів (R2, R3)**:
  - Порожні варіантні папки (`..._#<hash>`) або папки, що містять лише службові файли `desktop.ini`, автоматично переміщуються у Кошик без створення блокуючих конфліктів.
  - Дублікати файлів, створені хмарними провайдерами через конфлікти синхронізації (виду `... (1).pdf`), автоматично розпізнаються та надсилаються у Кошик.
- **Захист від масового повторного копіювання (R4)**: у режимі `repair_required` заблоковано виконання як `UpdateFile`, так і `CopyFile` для файлів, які вже відстежуються в `state.db`. Зміна лімітів більше не призводить до планування повторного викачування сотень гігабайт уже синхронізованих даних.
- **Скидання блокування `repair_required` (R5)**: прапорець `repair_required` у базі стану коректно знімається (`= 0`) після успішного планування та застосування відновлення цільових шляхів.
- **Підтримка екстремально глибоких каталогів**: динамічний розподіл резерву під ім'я файла усуває штучні винятки `Cannot fit directory within path limit` навіть на глибині понад 8 рівнів вкладеності.

## Оновлення з v0.3.17

1. Зупинити поточну версію WorkFlowSync.
2. Замінити `WorkFlowSync.exe` та `wfs.exe`.
3. Запустити програму.
4. Якщо для пари активний прапорець виправлення шляхів, виконати `wfs repair --pair "НАЗВА"` або скористатися пунктом «Виправити довгі шляхи» у меню завдання програми.
5. Після завершення перенесення та підтвердження синхронізації продовжувати регулярну роботу.
