## 🇺🇦 Опис релізу (Ukrainian)

Версія **v0.3.5** додає можливість паралельного виконання декількох завдань синхронізації одночасно, ізольоване блокування завдань, а також покращує відображення статусів і часу перевірки для нових пар тек. Завдяки цьому тривале копіювання файлів одного ресурсу більше не блокує регулярну синхронізацію інших завдань, забезпечуючи рівномірний обмін даними.

### 🌟 Що нового

#### 1. Паралельна синхронізація завдань (Parallel Task Execution)
- **Одночасне виконання завдань:** черга активних завдань тепер може оброблятися паралельно пулом потоків, запобігаючи ситуаціям, коли багатогігабайтне передавання файлів для однієї пари (наприклад, повної синхронізації Google Drive або мережевого сховища) заморожує синхронізацію решти папок.
- **Налаштування кількості одночасних завдань:** у розділі «Налаштування» → «Продуктивність сканера» з'явився числовий параметр «Одночасних завдань» (від 1 до 32, за замовчуванням 2), що дозволяє гнучко адаптувати навантаження під можливості каналу зв'язку та дискової підсистеми.
- **Підтримка в конфігурації:** параметр `MaxConcurrentPairs` зберігається у `config.json` та повністю валідується під час запуску і перевірки конфігурації утилітою `wfs config validate`.

#### 2. Ізольоване блокування окремих завдань (Granular Pair Locks)
- **Точкові замки завдань:** механізм міжпроцесного захисту `PassLock` переведений на гранулярні іменовані м'ютекси для конкретних завдань. Завдяки цьому виконання або сканування однієї пари не блокує інші пари.
- **Підтримка вибіркового запуску:** ручний запуск завдання з інтерфейсу («Перевірити зараз») або через консольну утиліту `wfs sync --once --pair <ім'я>` виконується негайно для обраного завдання, навіть якщо в цей момент інше завдання активно копіює файли.
- **Надійне збереження стану:** глобальне блокування конфігурації використовується для операцій над усім конфігом одразу або системних дій, гарантуючи транзакційну цілісність бази `state.db`.

#### 3. Чіткі статуси та виправлення відображення часу для нових завдань
- **Статус «Очікує синхронізації»:** щойно створені завдання або завдання, які ще жодного разу не запускалися, більше не позначаються помилковим зеленим статусом «Актуально». Для них виводиться нейтральний зрозумілий статус «Очікує синхронізації» («Pending sync»).
- **Час останнього проходу «Ще не синхронізувалося»:** у картках нових завдань замість чужого часу попереднього проходу виводиться підказка «Ще не синхронізувалося» («Never synchronized»).
- **Захист від хибного часу «щойно»:** виправлено поведінку, за якої при помилці блокування (якщо завдання вже зайняте) час синхронізації оновлювався на «щойно».

## 🇬🇧 Release Notes (English)

Version **v0.3.5** introduces parallel execution of multiple synchronization tasks, granular per-pair concurrency locking, and accurate status reporting for newly configured folder pairs. Lengthy file transfers for one resource no longer starve or delay sync operations for other tasks.

### 🌟 What's New

#### 1. Parallel Task Synchronization
- **Concurrent Task Processing:** The sync loop and runner now process active folder pairs concurrently using bounded semaphore pools, preventing high-volume sync jobs from holding up other folders.
- **Configurable Concurrency Limit:** Added the "Concurrent tasks" stepper under Settings → Scanner Performance (range 1–32, default 2) to optimize throughput according to network and disk bandwidth.
- **Configuration Schema & Validation:** The `MaxConcurrentPairs` option is fully integrated into `config.json` and validated by `wfs config validate`.

#### 2. Granular Task Locks
- **Per-Pair Mutex Isolation:** `PassLock` now acquires granular named mutexes per pair name. Scanning or syncing one task does not block other tasks.
- **Targeted Synchronization:** Manual execution from the GUI ("Check Now") or CLI (`wfs sync --once --pair <name>`) starts immediately for the selected pair, even while another background transfer is active.
- **Transactional Safety:** Global configuration lock remains active for bulk passes and maintenance operations, ensuring safe SQLite transactions.

#### 3. Clear Statuses & Accurate Timestamps for New Tasks
- **"Pending sync" Status:** Newly created tasks that have never executed now display an intuitive "Pending sync" status rather than falsely indicating "Up to date".
- **"Never synchronized" Timestamp:** Prevents newly added pairs from displaying inherited completion timestamps from prior global runs.
- **Accurate Failure Reporting:** Fixed an issue where lock contention or failed sync runs erroneously updated the task timestamp to "just now".
