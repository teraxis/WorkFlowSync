## 🇺🇦 Опис релізу (Ukrainian)

Версія **v0.3.12** розширює механізм звільнення місця у вихідній теці OneDrive (`freeUpSourceSpaceAfterCopy`), додаючи автоматичне виявлення та дегідратацію раніше синхронізованих файлів, а також впроваджує адаптивний цикл повторних спроб для надійного запису на хмарні віртуальні диски (Google Drive for Desktop).

### 🌟 Що нового

- **Ретроспективне звільнення місця джерела (OneDrive / Files On-Demand):** якщо для завдання увімкнено опцію «Звільняти місце джерела після копіювання», програма під час синхронізаційного проходу перевіряє вже наявні актуальні файли (`unchanged`, `adopted`). Якщо такий файл уже збережено в цільовій теці, але він локально завантажений у джерелі й не закріплений користувачем (`Pinned`), програма автоматично надсилає системну команду переведення його у стан «Лише в Інтернеті» (Online-only).
- **Адаптивний цикл повторних спроб (Retry Loop) для хмарних дисків:** операції запису, перевірки та фінального перейменування тимчасових файлів (`.wfs-tmp`) тепер використовують 6 прогресивних спроб з наростаючими паузами (50–250 мс). Це повністю усуває помилки блокування дескрипторів з боку процесу Google Drive for Desktop (`GoogleDriveFS.exe`) та затримки відображення файлів у віртуальній системі.
- **Журналювання вивантаження джерела (рівень INFO):** кожна операція звільнення місця у вихідній теці тепер фіксується у бойовому журналі у форматі `free-source  \<шлях>`, що забезпечує прозорий аудит вивільнення простору на диску.
- **Підтримка атрибутів у сканері директорій:** `TreeScanner` зчитує системні прапорці файлів (`FileAttributes`) безпосередньо з запису каталогу без жодного додаткового системного запиту на файл.

## 🇬🇧 Release Notes (English)

Version **v0.3.12** enhances source cloud offloading (`freeUpSourceSpaceAfterCopy`) with automatic dehydration of previously synchronized active files and introduces progressive retry loops for reliable writes to virtual cloud drives (Google Drive for Desktop).

### 🌟 What's New

- **Retrospective Source Space Offloading (OneDrive / Files On-Demand):** When «Free up source space after copy» is active, sync passes now inspect existing matching files (`unchanged`, `adopted`). If a file is confirmed on the target side but still hydrated locally in the source and not user-pinned (`Pinned`), WorkFlowSync automatically issues an online-only dehydration request.
- **Adaptive Retry Loops for Virtual Cloud Filesystems:** File writes, directory checks, and atomic moves of temporary `.wfs-tmp` files now incorporate a 6-attempt progressive backoff loop (50–250 ms). This completely mitigates opportunistic file locking by Google Drive for Desktop (`GoogleDriveFS.exe`) and virtual namespace visibility delays.
- **Informative Source Dehydration Logging (INFO level):** Source file offload events are now logged with `INFO` priority as `free-source  \<relative-path>`, offering clean and transparent storage auditability.
- **Fast Directory Attribute Ingestion:** `TreeScanner` captures `FileAttributes` directly during directory enumeration without performing redundant per-file disk lookups.
