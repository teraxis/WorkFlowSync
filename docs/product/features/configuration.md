# F6. Конфігурація

**Статус**: затверджено; парсер і валідація реалізовані (Етап 0) —
`src/WorkFlowSync.Core/Config/SyncConfig.cs`. Приклад: `config.example.json`.

## Файл

**Портативне розміщення (вимога замовника 2026-09-15): усі файли програми — `config.json`, `state.db`,
`logs\` — зберігаються в папці, з якої запущено `WorkFlowSync.exe` / `wfs.exe`.** Робоча тека
процесу (CWD) не має значення: шлях береться від розташування exe (`AppContext.BaseDirectory`),
тож і Планувальник із CWD = System32, і ярлик автозапуску знаходять ті самі файли. На першому
запуску GUI одразу створює `config.json` із типовими значеннями, щоб папка була «повною».

`config.json` поруч з exe (або `--config <шлях>` для тестів). JSON з коментарями `//` і кінцевими
комами. Кодування UTF-8. Відносні `statePath`/`logPath` — від папки конфігу; на сторінці
«Налаштування → Файли програми» показано папку програми, кнопку «Відкрити» і розв'язані абсолютні
шляхи бази й логів.

```json
{
  "pairs": [
    {
      "name": "vrp",
      "source": "E:\\vrp",
      "target": "D:\\OneDrive\\Робоча папка",
      "links": "follow",
      "retention": "365.00:00:00",
      "exclude": [ "\\Друга дисциплінарна палата\\*Робочий.docx" ]
    }
  ],
  "statePath": "state.db",
  "logPath": "logs",
  "logKeepDays": 30,
  "interval": "00:30:00",
  "scanParallelism": 8,
  "scanBufferSize": 262144
}
```

## Поля

| Поле | Тип | За замовчуванням | Опис |
|------|-----|------------------|------|
| `pairs[]` | масив | — | обов'язково ≥ 1 |
| `pairs[].name` | рядок | — | стабільний ключ пари в базі стану; **перейменування осиротить записи** |
| `pairs[].enabled` | так/ні | `true` | стан пари: `true` — «виконується» (перевіряється автоматично кожні `interval`), `false` — пауза. Ручний запуск (кнопка **Перевірити зараз** або `wfs sync --pair`) працює в обох станах. Пишеться самою програмою при натисканні ▶/⏸ |
| `pairs[].source` | шлях | — | корінь джерела (UNC або підключений диск); лише читання |
| `pairs[].target` | шлях | — | корінь локального дзеркала |
| `pairs[].links` | `follow` / `skip` / `recreate` | `follow` | F4 |
| `pairs[].retention` | TimeSpan / null | null (вічно) | F3; формат `d.hh:mm:ss` |
| `pairs[].exclude[]` | шаблони | `[]` | відносно кореня джерела; синтаксис FFS: `\папка\*.docx`, `*\~$*` |
| `statePath` | шлях | `state.db` | F2 |
| `logPath` | папка | `logs` | F8 |
| `logKeepDays` | 1..3650 | 30 | F8: скільки днів зберігати `wfs-*.log`; старіші видаляються при наступному проході. У GUI — «Налаштування → Файли програми → Зберігати журнали» |
| `interval` | TimeSpan | `00:30:00` | період у `--loop` і в автоперевірці з вікна; мінімум 1 хв |

| `scanParallelism` | 1..64 | 8 | F5 |
| `scanBufferSize` | ≥ 4096 | 262144 | F5 |

## Виключення

Синтаксис сумісний із FreeFileSync (список можна перенести вручну як є): шлях відносно
кореня джерела з провідним `\`; `*` і `?`; шаблон без `\` на початку збігається в будь-якій
папці. Порівняння без урахування регістру. Виключений об'єкт у базу не потрапляє. Виключення
застосовуються до сканера (в папку-виключення не спускаємось).

## Валідація

`wfs config validate` виводить пари і проблеми; код виходу 2 при помилках.
Перевірки: є пари; імена непорожні й унікальні; source/target непорожні; retention > 0;
interval ≥ 1 хв; parallelism 1..64; buffer ≥ 4096. Етап 1 додасть: target не всередині source
і навпаки; пари не перетинаються цілями.

## Сценарії приймання

1. `config validate` на `config.example.json` → `config: OK`, код 0 (виконано в Етапі 0).
2. Дві пари з іменем `vrp`/`VRP` → повідомлення про дублікат, код 2 (тест є).
