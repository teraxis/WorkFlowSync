# F12. Дизайн-система і теми

**Статус**: реалізовано 2026-09-14 (вимога замовника: «зробимо темну і світлу тему, дизайн має бути
більш якісним»). Файли: `src/WorkFlowSync.App/Styles/` (`Palette.axaml`, `Controls.axaml`,
`Icons.axaml`), `Converters.cs`, `Core/Config/AppTheme.cs`.

## Принципи

1. **Один набір токенів — дві теми.** Усі кольори оголошені як ресурси у `Palette.axaml` у двох
   словниках (`Light` / `Dark`). Жоден колір не прописаний у розмітці двічі; правила стилів спільні.
2. **Глибина — поверхнями, а не тінями.** Чотири рівні: полотно → рейка/панель дій → картка →
   утоплений блок, плюс волосяні межі (`BorderSubtle` / `BorderStrong`). Тіней немає: у темній темі
   вони брудні, у світлій — шумні.
3. **Один акцент.** Синій `#2C62E8` (світла) / `#4C82F7` (темна) лише для головної дії, вибраного
   пункту навігації, фокуса. Стан пари показують семантичні кольори (зелений / нейтральний сірий).
4. **Сітка 4 px, три радіуси** (6 / 10 / 14) і «пігулка» для круглих кнопок і бейджів.
5. **Типографіка зі шкали**: `display` 22 · `title` 16 · `body` 13.5 · `caption` 12 · `mono` 12.5
   (Consolas для шляхів і журналу). Заголовки секцій — 12 px, великі літери, розріджені.

## Класи стилів

- Кнопки: `primary` (акцент), звичайна, `ghost` (без рамки), `danger`, `accentsoft`, `icon` (кругла 38 px).
- Контейнери: `card`, `sunken`, `divider`, `badge` (+`success`), `row` (рядок пари).
- Текст: `display`, `title`, `section`, `secondary`, `caption`, `mono`, `danger`, `oneline`
  (без переносу, з трикрапкою — щоб довгі шляхи не ламали розкладку).
- Списки: `nav` (рейка), `rows` (пари).

## Іконки

`Icons.axaml` — геометрії 24×24 двох родин:

- **контурні** малюються обведенням: `<Path Classes="ico" Data="{StaticResource IconFolders}" />`;
- **суцільні** — заливкою: `<Path Classes="icof" Data="{StaticResource IconPlayFill}" />`.

Колір задають стилі за класом кнопки (`Button.primary Path.ico` тощо), тож іконка завжди
контрастна до підкладки й реагує на наведення. `PathIcon` не використовуємо: він **заливає**
контур, і контурні іконки перетворюються на чорні плями (спіймано на першому скриншоті).

## Структура вікна

```
┌──────────────┬──────────────────────────────────────────────┐
│ рейка 248 px │ заголовок сторінки + дії                      │
│  лого+версія │──────────────────────────────────────────────│
│  Папки       │ вміст сторінки (картки)                      │
│  Синхроніз.  │                                              │
│  Налаштув.   │──────────────────────────────────────────────│
│  ──────────  │ панель дій: статус · Перевірити · Скасувати · │
│  стан фону   │                                    Зберегти  │
└──────────────┴──────────────────────────────────────────────┘
```

Рейка завжди показує стан фонової перевірки (крапка + один рядок), тож він видно з будь-якої
сторінки. Панель дій з «Зберегти» теж постійна — правило «зміни застосовуються після збереження»
не залежить від того, де користувач зараз.

## Теми

`config.json` → `theme`: `System` (за замовчуванням) / `Light` / `Dark`; перемикач — «Налаштування →
Вигляд», застосовується миттєво (`Application.RequestedThemeVariant`). `System` слідує за темою
Windows.

## Службовий аргумент

`WorkFlowSync.exe --page <0|1|2>` відкриває потрібну сторінку — для документації та налагодження
вигляду. Сторінку треба ставити **після** показу вікна: рейка при ініціалізації записує власний
`SelectedIndex` у прив'язку й затирає раніше встановлене значення.

## Сценарії приймання

1. Світла й темна теми: усі три сторінки читабельні, контраст тексту ≥ 4.5:1, жодного «вибитого»
   контрола зі стандартної теми Fluent. ✅ (скриншоти 2026-09-14)
2. Довгі шляхи не ламають рядок пари: обрізаються трикрапкою, повний шлях — у підказці. ✅
3. Перемикання теми не потребує перезапуску. ✅
4. Іконки видно в обох темах і на акцентних кнопках. ✅

## Відкриті питання

- Локалізація uk/en (зараз тексти українською в розмітці).
- Анімації переходів між сторінками — навмисно не додано: зайвий рух у службовій програмі.
