# F4. Обробка лінків у джерелі

**Статус**: затверджено (2026-09-14). Реалізація: `follow` і `skip` — Етап 1; `recreate` — після.

## Контекст

У мережевій папці частина «папок» — це лінки: symlink, junction, DFS-посилання. У FreeFileSync
для них є окрема опція; у поточному конфігу замовника стоїть `<Symlinks>Follow</Symlinks>`.
Файли `.lnk` — це звичайні файли, а не лінки файлової системи; вони копіюються як файли.

## Режими (параметр пари `links`)

| Режим | Поведінка | Коли |
|-------|-----------|------|
| `follow` (за замовчуванням) | Пройти крізь лінк; у цілі створити **справжню папку** з вмістом | OneDrive не синхронізує symlink/junction — у дзеркалі мають бути тільки справжні об'єкти |
| `skip` | Ігнорувати лінк повністю | лінк веде у величезний або чужий архів |
| `recreate` | Створити такий самий лінк у цілі | не для OneDrive; symlink для звичайного користувача потребує Developer Mode (junction — ні). Відкладено |

Точкове вимкнення конкретного лінка при `follow` — через `exclude` пари.

## Виявлення

Об'єкт із `FileAttributes.ReparsePoint`. Ціль: `FileSystemInfo.ResolveLinkTarget(returnFinalTarget: true)`.
Серверні symlink'и по SMB зазвичай розв'язуються на боці сервера і виглядають як звичайні папки —
тоді жодної спецобробки не треба; junction/DFS можуть прийти як reparse point.

## Вимоги до `follow`

1. **Захист від циклів.** Набір відвіданих *реальних* шляхів (після `ResolveLinkTarget`,
   нормалізованих, `OrdinalIgnoreCase`). Повторний вхід у вже відвідану реальну папку — пропуск
   з попередженням у лог. FFS від цього не захищає.
2. **Ключ у базі — логічний шлях** (як користувач бачить крізь лінк), а не реальний. `first_seen`,
   tombstone, ретенція працюють однаково для звичайних і прилінкованих папок; локальне видалення
   такого вмісту не повертає його (правило 3).
3. **Недоступна ціль лінка** (лінк на відключений шар) → гілка трактується як «джерело недоступне»:
   нічого не видаляти, не позначати, у лог — попередження.
4. `via_link = 1` у записах — лише для діагностики, на логіку не впливає.
5. Обмеження глибини вкладення лінків (наприклад, 8) — запобіжник проти патологічних дерев.

## Сценарії приймання

1. Джерело має junction `Архів → \\srv\archive\2020`. `follow` → у цілі `Архів\` як звичайна папка
   з файлами; у базі шляхи `Архів\...`, `via_link = 1`.
2. Junction веде на батьківську папку → сканер не зациклюється, у лозі одне попередження.
3. `\\srv\archive` вимкнено → прохід завершується успішно; гілка `Архів\` без змін; попередження.
4. `links: skip` → `Архів\` у цілі не створюється.
