# Погодження змін та версіонування файлів (.wfsversions)

## Призначення

Функціонал погодження змін та версіонування (Етап 6) призначений для двобічних пар синхронізації (`twoWay`), де зміни у локальній (другій) теці B не переносяться на спільний сервер A автоматично, а потребують підтвердження користувача.

## Основні поняття

1. **Модерована тека (B)**: Друга, локальна тека (типово у OneDrive), у якій працює користувач.
2. **Вихідна тека (A)**: Перша тека (мережеве сховище або сервер).
3. **Погодження змін (`RequireApproval`)**: Режим, за якого будь-які створення, зміни, видалення, перейменування чи переміщення у теці B фіксуються в черзі `pending` та чекають на рішення людини.
4. **Версіонування (`.wfsversions`)**: Зберігання локальних копій файлів перед їх поверненням (відкатом) або видаленням у прихованій теці `.wfsversions` з ротацією за віком і обсягом.

---

## Черга погодження та три рішення

| Подія в B | Підтвердити (✓) | Залишити як є (✕) | Повернути (↶) |
|-----------|-----------------|-------------------|---------------|
| Файл змінено | Скопіювати B → A, статус `Active` | Зафіксувати обидва боки, статус `Diverged` | Відновити з A (копія B → `.wfsversions`), скопіювати A → B |
| Файл видалено | Видалити в A (Кошик / `.wfsversions`) | Зафіксувати статус `Tombstone` | Скопіювати A → B |
| Файл додано | Скопіювати B → A | Зафіксувати статус `LocalOnly` | Перенести файл у `.wfsversions` або Кошик, прибрати з B |
| Перейменовано / переміщено | `Move` у A | Статус `Diverged` на обох шляхах | `Move` назад у B |
| Конфлікт | Лишити версію B, скопіювати B → A | Статус `Diverged` | Лишити версію A, скопіювати A → B |

## Версіонування (`.wfsversions`)

- **Структура**: `\.wfsversions\<yyyy-MM-dd_HHmmss>\<відносний_шлях>`
- **Прихованість**: Тека створюється з атрибутом `Hidden` та файлом `README.txt`.
- **Правило**: Версіонується лише те, що не можна отримати з першої теки або Кошика (відкат додавання/зміни, видалення на мережі без Кошика, програшна сторона конфлікту).
- **Ротація**: Прибирання за днями (`versionsKeepDays`, за замовчуванням 30) та обсягом (`versionsMaxGb`, за замовчуванням 5 ГБ).

---

## Конфігурація (`config.json`)

```json
{
  "name": "Документи ВРП",
  "mode": "twoWay",
  "requireApproval": true,
  "approvalSide": "target",
  "versioning": true,
  "versionsPath": ".wfsversions",
  "versionsKeepDays": 30,
  "versionsMaxGb": 5
}
```

## CLI-команди

- `wfs pending list [--pair <назва>] [--json]` — перегляд відкритих записів у черзі;
- `wfs pending approve (--id <n> | --path <шлях> | --all) [--pair <назва>] [--yes]` — підтвердити зміну;
- `wfs pending dismiss (--id <n> | --path <шлях> | --all) [--pair <назва>] [--yes]` — залишити як є;
- `wfs pending revert (--id <n> | --path <шлях> | --all) [--pair <назва>] [--yes]` — повернути стан;
- `wfs status` — додано вивід `pending=N` та ненульовий код виходу при наявності черги.

## Графічний інтерфейс погодження змін (Approval Window)

- **Візуальні бейджі типів змін**: кругла піктограма з відповідним кольором (зелений `+` для доданих, червоний кошик для видалених, бурштиновий олівець для змінених, синя стрілка для перейменованих/переміщених, щит для конфліктів) та дельта розміру (`+5 KB`, `−2 KB`).
- **Фільтрація у селектах**: випадні списки-селекти з чекбоксами для вибору завдань (пар) та типів змін із підрахунком подій (`Додано (N)`, `Змінено (N)`, `Видалено (N)`, `Перейменовано (N)`), підтримкою трипозиційного «Обрати всі» та динамічним зведенням на кнопках («Усі зміни», «Обрано: 2» тощо).
- **Позначення відсутніх елементів**: замість прочерків використовується акуратний курсивний напис «відсутнє».
- **Дії для кожного рядка**: ідеально центровані круглі кнопки 32×32 з кольоровою підсвіткою та підказками (Підтвердити, Залишити як є, Повернути).
- **Формат дат**: `dd.MM.yyyy HH:mm:ss`.
