# F9. Міграція з FreeFileSync

**Статус**: реалізовано (Етап 2, 2026-09-14) — `Core/Ffs/FfsBatchImporter.cs`, `wfs import-excludes`,
кнопка **Імпорт із FreeFileSync…** на вкладці «Папки», `wfs forget`. Перевірено на бойовому файлі:
22 548 глобальних записів → 16 шаблонів + 22 551 tombstone за 0,3 с (dry-run, без стату джерела).

## Вихідна точка

`D:\OneDrive\Робоча папка\App\freefilesync\batch.ffs_batch` (XmlFormat 23):

- пара `E:\vrp\` → `E:\OneDrive\Робоча папка\`, порівняння `TimeAndSize`, `Symlinks=Follow`;
- зміни: `Left Create=right Update=right Delete=none`, `Right — none` (тобто саме правила 1–2);
- `<Exclude>` — **22 569** шляхів: ручна реалізація правила 3 (те, що користувач видалив локально);
- запуск через Планувальник завдань Windows.

## Команда `import-excludes`

```
wfs import-excludes "D:\...\batch.ffs_batch" [--pair <name>] [--dry-run] [--no-probe] [--config config.json]
```

1. Читає `<FolderPairs>`; кожна FFS-пара зіставляється з парою конфігу за **джерелом** (`Left`,
   без урахування регістру й кінцевого `\`) або береться явно через `--pair`. Пара без
   відповідника — повідомлення «додайте пару і повторіть» (пари не створюються автоматично: ціль
   у FFS могла переїхати, як `E:\OneDrive` → `D:\OneDrive`).
2. Читає глобальний `<Filter><Exclude>` і фільтр пари:
   - записи з шаблонами (`*`, `?`) → у `exclude` пари (дублікати не додаються);
   - конкретні шляхи → у базу стану як `tombstone` з `first_seen = status_changed = момент
     імпорту`; `kind` — стат у джерелі, якщо воно доступне (`--no-probe` вимикає), інакше за
     наявністю розширення. Наявний `active`-рядок конвертується в `tombstone`; наявний
     `tombstone` пропускається.
3. Звіт за парою: шаблонів/tombstone додано, вже було, конвертовано. `--dry-run` нічого не пише
   (навіть `state.db` не створює).

У GUI те саме робить кнопка **Імпорт із FreeFileSync…** (вкладка «Папки»): tombstone пишуться
одразу, нові шаблони потрапляють у поле «Виключення» пари і чекають на **Зберегти**.

Результат: перший прохід WorkFlowSync **не повертає** жоден із 22 569 файлів — перехід
безшовний.

## Порядок переходу

1. Вимкнути завдання FFS у Планувальнику (не видаляти).
2. Додати пару в GUI (джерело = `Left` з FFS, дзеркало = актуальна папка OneDrive), **Зберегти**,
   потім **Імпорт із FreeFileSync…** (або `wfs import-excludes …`), **Зберегти** ще раз.
3. `sync --once --dry-run` — переглянути план (очікувано: майже нуль копіювань, бо FFS уже
   все синхронізував; `active` для наявних; ніяких видалень, поки не задано `retention`).
4. `sync --once` → перевірити лог.
5. Увімкнути автозапуск/завдання WorkFlowSync (F7).
6. Задати `retention` лише після кількох успішних проходів і перегляду `--dry-run`.

## Наявні локальні файли на першому проході

Об'єкти, які вже є і в джерелі, і в цілі (їх скопіював FFS), потрапляють у базу як `active`
з `copied_* = фактичні атрибути цілі` (таблиця рішень F1, рядок «нема / є / є»). Якщо `S ≠ L`
— `local_modified`, бо ми не знаємо, хто правий, а правило 3 велить не чіпати локальне.

## `forget`

```
wfs forget "<відносний шлях>" [--pair <name>]
```

Видаляє з бази запис шляху і всього піддерева (без урахування регістру) — об'єкт знову вважається
невідомим і на наступному проході з'явиться як новий (якщо є в джерелі). Спосіб «передумати»
щодо tombstone.

2. `sync --once --dry-run` після імпорту на реальних папках → 0 копіювань для файлів зі списку
