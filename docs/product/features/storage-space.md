# F22. Керування місцем на диску

**Статус**: реалізовано 2026-09-21.

## Мета

Велике первинне копіювання не повинно заповнювати диск швидше, ніж сховище встигає обробити
файли. Налаштування зібрані в окремому розділі завдання «Параметри системи» і не залежать одне
від одного:

- `diskQuotaEnabled` + `minFreeSpaceGb` — захист заданого резерву для будь-якої кінцевої теки,
  зокрема на локальному, знімному або мережевому диску;
- `freeUpSpaceAfterCopy` — команда Windows зробити нову копію доступною лише онлайн; лише для
  OneDrive або іншого зареєстрованого Files On-Demand sync root;
- `rotateOnLowSpace` — аварійне остаточне видалення найстаріших безпечних копій у будь-якій
  кінцевій теці й разом із дисковою квотою. Працює в `mirror` і `twoWay`.

## Дискова квота

1. Перед проходом програма порівнює вільне місце з `minFreeSpaceGb`. Якщо резерв уже вичерпано,
   прохід не додає нових файлів; за дозволеної ротації спочатку робиться спроба звільнити місце.
2. Перед кожним наступним цільовим записом потрібно мати резерв плюс повний розмір файла.
3. Для будь-якої цілі нестача місця зупиняє решту цільових копій цього проходу. Наступний
   автоматичний прохід повторить перевірку.
4. Для Files On-Demand теки з активним `freeUpSpaceAfterCopy` прохід може чекати, поки хмарний
   клієнт вивантажить уже закриті файли та поверне потрібний резерв.

Квота не вмикає хмарне вивантаження або ротацію автоматично.

## Вивантаження в хмару

Програма перевіряє реєстрацію кінцевої теки через Windows Cloud Files API, а не за назвою шляху.
Після атомарного запису вона встановлює атрибут `Unpinned` і знімає `Pinned` — системний еквівалент
команди «Звільнити місце». OneDrive або інший провайдер сам виконує передавання асинхронно.

Токен Microsoft, Microsoft Graph, реєстрація застосунку та права адміністратора не потрібні.
WorkFlowSync не керує швидкістю чи чергою провайдера. Якщо ціль не є Files On-Demand сховищем
або команда завершується помилкою, подальші цільові копії проходу зупиняються.

## Ротація

Ротація — свідомий вузький виняток із правила «локальні видалення через Кошик». Вона виконує
`File.Delete` без Кошика лише коли одночасно виконані всі умови:

1. користувач явно ввімкнув `diskQuotaEnabled` і `rotateOnLowSpace`;
2. рядок стану має `active`, `copied_at`, `copied_size` і `copied_mtime`, тобто цей файл справді
   був записаний поточною версією програми;
3. безпосередньо перед видаленням розмір і дата зміни на диску ще збігаються зі станом; змінений
   користувачем файл, невідомий файл або сторонній reparse point не видаляються. Підтверджений
   Files On-Demand placeholder усередині свого sync root може бути кандидатом.

Кандидати сортуються за `copied_at` (час успішного копіювання), за однакового значення — за
фактичною датою зміни, потім створення і шляхом. Після кожного видалення програма перевіряє місце
знову й зупиняється одразу після відновлення резерву. Кожен файл логується як `WARN` із повним
шляхом, а його рядок негайно стає `tombstone`, тому перша/вихідна тека лишається недоторканою і
копія не повертається наступним проходом. У `twoWay` tombstone також блокує поширення видалення
на першу теку. Порожні теки ротація не видаляє.

Після оновлення старі рядки стану мають `copied_at = null` і не є кандидатами. Файл стане
кандидатом тільки після нового успішного копіювання або оновлення програмою.

## Сценарії приймання

1. Усі три опції вимкнені → поведінка старих конфігів не змінюється.
2. Увімкнена лише квота для будь-якої кінцевої теки → нестача місця зупиняє нові записи без
   видалення файлів.
3. Увімкнене лише хмарне вивантаження в OneDrive → успішні копії отримують online-only intent;
   квота не вмикається неявно.
4. Увімкнені квота й хмарне вивантаження → програма не переходить резерв і чекає на провайдера.
5. Увімкнені квота й ротація у будь-якій кінцевій теці → найстаріші незмінені власні копії
   остаточно видаляються до відновлення резерву та стають tombstone. У хмарній теці провайдер
   може синхронізувати видалення з хмарою.
6. Найстаріший файл змінено локально → його збережено; програма переходить до наступного
   безпечного кандидата.
