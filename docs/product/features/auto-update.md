# Автоматичне оновлення

## Призначення

Програма автоматично перевіряє наявність нових версій на GitHub і пропонує оновити себе
без ручного пошуку, завантаження та заміни файлів.

## Як працює

### Перевірка

При запуску (і раз за сеанс) програма звертається до GitHub Releases API:

```
GET https://api.github.com/repos/teraxis/WorkFlowSync/releases/latest
```

Порівнює `tag_name` з поточною версією (`WorkFlowSyncInfo.Version`). Якщо на GitHub є новіша
версія — показує повідомлення. Якщо мережі немає або API недоступний — перевірка тихо
пропускається.

### Повідомлення

Вікно-повідомлення з'являється біля системного трею (аналогічно сповіщенням про нові файли):

- **Заголовок:** «Доступна нова версія»
- **Текст:** номер версії і пропозиція оновити
- **Кнопки:**
  - «Оновити» — завантажує новий exe з GitHub і встановлює
  - «Нагадати пізніше» — закриває вікно; перевірка повториться при наступному запуску
  - «Не нагадувати про це оновлення» — записує номер версії в `skippedVersion` конфігу

### Завантаження та встановлення

При натисканні «Оновити»:
1. Кнопки замінюються прогрес-баром
2. Новий exe завантажується як `WorkFlowSync.update.exe`
3. Створюється тимчасовий скрипт `wfs-update.cmd`, який:
   - Чекає завершення поточного процесу
   - Переміщує старий exe → `WorkFlowSync.old.exe`
   - Переміщує `WorkFlowSync.update.exe` → `WorkFlowSync.exe`
   - Запускає нову версію
   - Прибирає тимчасові файли
4. Програма завершує роботу, скрипт виконує заміну

При наступному запуску нова версія прибирає залишки (`WorkFlowSync.old.exe`, `wfs-update.cmd`).

## Конфігурація

```json
{
  "autoUpdate": true,
  "skippedVersion": null
}
```

| Поле | Тип | Типово | Опис |
|------|-----|--------|------|
| `autoUpdate` | bool | `true` | Чи перевіряти нові версії при запуску |
| `skippedVersion` | string? | `null` | Версія, про яку не нагадувати |

У вікні налаштувань — checkbox «Автооновлення (перевіряти нові версії на GitHub)» у секції
«ОНОВЛЕННЯ».

## Вимоги до релізів GitHub

Щоб автооновлення працювало, кожен GitHub Release повинен містити:
- Tag з версією (наприклад `v0.2.0`)
- Asset з іменем `WorkFlowSync.exe` (single-file, self-contained, win-x64)

## Обмеження

- Працює лише для Windows (bat-скрипт для самозаміни)
- Потрібен доступ до інтернету (GitHub API)
- Ліміт API: 60 запитів на годину для неавторизованих клієнтів (достатньо)
- Портативна програма замінює лише один exe; якщо поруч лежать інші файли — вони залишаються
